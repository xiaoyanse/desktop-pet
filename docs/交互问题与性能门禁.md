# 交互问题与性能门禁

更新：2026-10-12。来源为用户本轮反馈和当前源码取证；本文件记录过程，不把讨论、素材、代码接入或单测通过当作实际验收。

最新变更：用户取消100 MB硬上限，尽量优化，先完成全部已确认功能闭环。以下P01及超限记录为原要求下的历史结果，仍可用于后续优化，但不再阻挡功能推进。软件候选实验两轮峰值约72 MB，大窗口仍慢且最新一轮提前退出未定位，未替换正式后端；普通应用保留已有字体/图集优化。记录见《原生软件绘制实验》。

## 用户追加要求

1. 宠物悬停大部分时候无法打开螺旋，必须可靠重复触发。
2. 一级、二级动画有黑边、卡顿及方向异常；完整检查中间帧，不能仅看最终截图。
3. 点击固定位置后操作栏未收起；全面检查悬停、离开、关闭、固定、穿透、恢复和模式切换。
4. 需求、发现、取证和过程持续落盘，不仅留在聊天中。
5. 所有应用状态内存不得超过 100 兆。暂按更严格的 100,000,000 字节（约 95.37 MiB）执行，而不是把 100 MiB 当作 100 MB。工作集、私有内存与各自峰值均记录，不能靠主动清工作集、测量结束前释放或只测空闲来达标。

## 本轮顺序与验证

先建立 H01 可确定复现的失败用例，修复状态生命周期；同时统一触发/锁定/恢复和活动入口检查。动画拆分原生区域与绘制变化，补镜像轨迹及中间帧回归。用户追加 100 MB 要求立即纳入容量、缓存与资源生命周期设计，达不到不能称性能完成。

当前未提交螺旋边界修复也纳入同轮：限制实际绘制边界、动画中禁止触发二级工作、收缩确认卡多余空白、替换不一致设置图标。完整检查后阶段本地提交，不推送、不打 tag。

日常悬停、实际连续帧、全 DPI/多屏以及长期内存上限分别记录；无实测则明确未验证。开发不执行真实清理、录音或截图用户桌面，不结束用户其他工作进程。Computer Use 当前接口没有单纯鼠标移动/悬停方法，不用试用窗的点击验证冒充日常反复悬停验收。

## 实机发现与失败记录

第一轮修改版本（12:25:48 构建，8,748,032 字节，PID 36200）经过真实试用仍见三颗分类图外围黑圈，证据 `evidence/hover-black-first-level-20261012.png`。原始 RGBA 外圈抽样均为 0,0,0,0，证明至少抽样处原图透明，不将问题草率归结为 AI 图像黑背景。继续检查 Windows OpenGL/DWM 透明合成与窗口区域，尚未验证后续修复结果。

同 PID 三分钟预算检查覆盖设置打开、移回屏幕内、最大化、外观页及一级试用。`evidence/hover-animation-memory-budget.json`：180.004 秒，工作集 108.23–145.27 MiB，系统记录进程生命周期工作集峰值 160,714,752 字节，采样私有峰值 101,072,896 字节，生命周期提交峰值 104,210,432 字节，CPU 均值 0.7671%。门禁明确失败并返回非零，不据此声称性能达标，也不与其他场景作优化因果比较。

另外发现设置窗口恢复时左侧越出工作区 55 像素（实机 inspect 边界 -55,247,985,1067），手动原生拖回后可见。本轮尚未给恢复边界自动约束补完整回归，登记 H07；用户期间正常改变桌面视图和位置，不能盲目覆盖恢复早期配置快照。

新回归检查 100 次离开/再次进入、锁定后没有按钮绘制和动作、清理确认/保持展开/试用标志统一清除、两个层级 0–250ms 每毫秒镜像轨迹和边界。第一轮完整检查 97 单元＋2 切图＋1 架构通过，严格 clippy 和 release 构建通过；这一组绿色结果未拦住真实黑圈，说明必须继续实机而非宣称动画已完成。
