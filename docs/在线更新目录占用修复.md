# 在线更新目录占用修复

2026-10-13：用户从已安装的0.2.1升级0.2.2，弹出“原程序目录被占用或没有写入权限，未替换文件”。
这不是下载或差分解码失败，两个现场job已完整下载到payload，目标仍为原始0.2.1散列。

## 根因及可重复证据

现场辅助进程PID28668位于E:/DesktopMeterData/updates/stage-1791896389383146300/helper.exe，
仅读取该进程的当前目录字段确认其CurrentDirectory=E:/Apps/DesktopMeter/current/。
install::launch没有指定工作目录，helper也没有离开继承的目录。
Windows会保持工作目录句柄，因此辅助进程自己占用了replace要重命名的目录。
原程序已经退出，但该占用仍存在；通用报错隐藏了具体系统错误。

E:/Temp/desktop-meter-update-cwd-20261013/live-helper-cwd.json为现场证据。
使用原始0.2.1辅助程序及隔离Rust子程序，强制WorkingDirectory为待更新application目录，
在E:/Temp/desktop-meter-update-native-20261013-210429/success/helper.stderr.txt确定性复现同一句报错。
不改文件和程序，仅从stage目录重启同一隔离任务即更新成功，
E:/Temp/desktop-meter-update-cwd-20261013/cwd-only-recovery.json为绿灯证据。

## 本次现场恢复

先确认原程序未重新运行、当前目录四文件齐全、原始/下载/辅助EXE散列分别匹配job。
只结束此任务已报错的辅助进程，从stage重启原辅助EXE处理原下载任务。
新程序收到1791896389383146300:0.2.2健康确认，helper退出0；
E:/Apps/DesktopMeter/current/desktop-meter.exe散列等于公开0.2.2，
PID35648于2026-10-13 21:07:50启动，旧版保存在current.previous-1791896389383146300。
证据E:/Temp/desktop-meter-update-cwd-20261013/live-recovery.json。
这是人工调整辅助进程启动条件后完成的现场更新，不能称旧版原生GUI链路已无缺陷。
没有修改权限、关闭其他应用、删除旧版或更改个人设置/便签文件。

## 修复及为何原测试漏检

0.2.3在launch时明确指定stage工作目录，helper入口再次切换到stage，
然后才等待原程序退出并替换。失败写入result.txt，重命名失败附具体OS错误。
并行单元测试不修改进程级工作目录；切换只发生在单独的更新辅助进程。

之前verify-update-native.ps1从开发项目目录启动辅助进程，
没有模拟资源管理器/快捷方式把程序目录作为工作目录的条件，导致成功测试漏检。
现在成功与回退两例都显式把初始工作目录设为待更新目录，生产helper必须主动离开。
另补外部目录不共享删除的句柄占用回归，要求原目录/payload均保留并带OS错误，
不以强杀其他进程解决外部占用。

0.2.1/0.2.2是已发布的旧更新器，下载0.2.3不能预先改变旧辅助程序。
旧版本若报此错误，可使用安装包一次修复升级，或正常退出后从程序目录之外启动再更新。
本机已恢复的0.2.2继承stage工作目录，可继续测试下一次升级。
旧0.2.2产物不覆盖；修复包版本0.2.3，以精确0.2.2包为增量基线。
最终测试、构建、包散列及发布记录随后登记《Windows安装与增量更新》。
