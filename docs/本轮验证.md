## 验证结果与证据

`cargo test`：27 项单元测试及 1 项架构测试通过。`cargo clippy --all-targets -- -D warnings` 通过。release 构建通过，程序实际运行。检测与测试未执行任何系统内存清理操作。

真实 egui 输入测试覆盖鼠标按下/释放、隐藏工具栏首次命中、完整与精简模式图标切换。真实 Windows 消息型命名管道测试覆盖 JSON 返回、对端 PID、可执行文件来源和客户端关闭后读取；只发送测试错误字符串，没有启动提升 helper 或清理内存。

在本机运行的程序上实际打开并检查监测、外观、清理页面与原生右键菜单；图标导航、中文、AI 标识、滑块、分组与空态均可见。用户原有监测项与 47% 背景透明度保留，没有为截图覆盖其设置。

实际点击图标完成完整 → 精简 → 完整：当前四项内存指标由 240×142 缩为 240×62，再还原。证据：`evidence/final-compact.json`、`evidence/final-restored.json`。该尺寸只对应当前启用指标，不是固定默认尺寸。

实际连续向右拖动窗口，抵达工作区最右侧后继续向外拖。窗口保持 `[2320, 0, 2560, 142]`，工作区 `[0, 0, 2560, 1392]`，置顶有效，整窗未越界。证据：`evidence/final-right-edge.json`。负坐标显示器、缩放和其他边缘已做规则测试；没有在多显示器现场重复实操全部组合。

资源采样见 `evidence/modern-resources.json` 和 `evidence/final-resources.json`。采样场景为用户当前四个内存指标、2 秒刷新、未展开进程排行、自动清理关闭；首轮 180 秒整机 CPU 平均 0.17%，工作集约 111–112 MiB。此结果不能代表开启全部 GPU、趋势图或进程详情时的开销，也不能据此称为长期稳定性验收。

## 旧验证为何没有拦住问题

1. **还原按钮失效**：此前静态检查仅确认切换分支存在，未跑真实 egui 鼠标交互。小窗口内的 egui 提示层覆盖按钮，下一帧点击被截走。改成窗口外原生提示，并保留工具栏稳定命中区；补按下/释放回归及实机点击。
2. **精简没有数值**：此前测试只覆盖类别分组，允许只画字母。现在测试名称、数值、两块 GPU 和缺失标记，精简模式采用两列名称与数值。
3. **右侧越界**：之前只测释放后的吸附，没有覆盖拖动中的整窗范围和不吸附场景。现在对移动中、释放后和尺寸变化约束整窗；补四边、负坐标、过大窗口测试并实机向右越界拖动。
4. **拖动与悬停切换**：GUI 刷新时机和滚动区域会影响快速拖动；改为 Windows 原生拖动面，并明确保留图标与详情操作区域。跨内容区域和工具栏的鼠标移动不应作为离开整个窗口处理。
5. **操作后测量失败丢记录**：原先后读数错误直接返回总错误，可能丢失已执行项目。现在保留逐项结果，测量失败时不显示内存变化；对应回归覆盖部分成功和读数失败。
6. **自动规则使用旧状态**：刷新失败后仍可能依据旧高负载状态执行。现在读取失败立即停止本轮自动判断；服务回归覆盖该分支和单任务执行约束。

## 宠物与托盘后续调整

- 第三种视图内置 AI 绘制的猫、狐狸、猫头鹰透明图集。窗口为 72×84 逻辑像素，保留资源状态数值。头部局部网格变形与眼睛局部 UV 位移跟随全屏鼠标；另外提供悬停抬头/呼吸、点击回应、拖放摇摆回弹和眨眼。动画最多约 15 帧/秒，鼠标稳定后约 5 次/秒更新，关闭动画停止全屏鼠标轮询。
- 宠物或清扫图标悬停打开独立原生快捷面板，不给卡片预留空白。还原、精简、设置、完整清理中心均可到达。快捷清理只构造低优先级待机缓存操作，不改用户的完整清理选择；未实际点击执行清理。
- 重复红横线来自进度条和持续超限下划线叠加；后者改为小红点。回归检查绘制结果只有一条红色进度矩形和一个红点，没有附加红色线段。
- 不同原生菜单操作使用独立矢量图形，测试逐对检查不同；实机悬浮右键菜单可见六种不同图标。
- 框架的 `with_taskbar(false)` 在 Windows 中通过 COM 移除任务栏按钮，未消除 Alt+Tab 的应用样式。增加原生 `WS_EX_TOOLWINDOW` 并清除 `WS_EX_APPWINDOW`，拦截后续样式更新保持策略，保留置顶和穿透；设置窗口不应用该策略。
- `cargo test -j 1`：35 项单元测试和 1 项架构测试通过；严格 clippy 通过。新增测试覆盖旧设置兼容、宠物模式互斥、显示位置、头部独立于身体、睁眼 UV 独立变化、鼠标各方向及边界、菜单图标区分与窗口样式。
- 实机已操作：宠物悬停展开、面板打开设置、外观中小猫切狐狸、宠物双击恢复完整卡片。最终版窗口样式证据 `evidence/final-shell-settings.json`：主窗 toolWindow=true、appWindow=false、topmost=true；设置窗 toolWindow=false、appWindow=true。隐藏的工具窗口不会被当前 Computer Use 枚举，最终版宠物与面板可通过设置入口切换和只读诊断验证。
- 旧测试只检查告警颜色和状态，没有检查实际绘制图形数量；菜单测试也未要求各项图形不同。补齐上述绘制和逐对比较回归。窗口样式过去只检查置顶，没有检查工具/应用标志，现纳入只读诊断。
- 本机首次并行编译因 Windows 提交量不足出现 OS 1455；改为单任务编译后验证通过，没有更改系统分页设置或结束其他工作进程。
- 宠物动画开启、狐狸形象、当前四个内存指标、5 秒数据刷新、设置和快捷面板关闭时连续采样 180.7 秒：整机 CPU 平均 0.129%，工作集 121.93–125.50 MiB，见 `evidence/pet-resources.json`。这是短时当前场景数据，不代表所有监测项、持续拖动/悬停场景或长期运行；内存仍是百兆级。`evidence/final-shell-pet.json` 确认最终版宠物为 72×84、置顶、工具窗口样式。
- 临时开启热键并实际按 Ctrl+Alt+C，只展开面板，没有执行清理。`evidence/final-shell-flyout.json` 确认快捷面板 toolWindow=true、appWindow=false，设置窗口仍保持普通应用样式。验证后恢复热键关闭，自动规则始终关闭。启动参数 `--settings` 已在已有实例上实际打开设置。
- 最终源代码通过 `cargo fmt --check`、`cargo test -j 1`、`cargo clippy --all-targets -j 1 -- -D warnings` 和 `cargo build --release -j 1`；应用的 `--quit` 正常退出命令已实际使用并保存设置，最终发布版已重新启动。只读现场状态见 `evidence/current-running.json`。本轮改动继续保留为未提交工作区。

## 清理档位与工作台改版（2026-10-12）

- 轻度、中度、重度分别含 1 / 2 / 4 项；原有自定义选择保持为自定义，没有强行覆盖。当前清单、适用场景、影响说明均直接可见；全部八项仍可高级自定义。
- 主操作改为 48 像素全宽图标加文字按钮，高级选择折叠。快捷面板复用主按钮与固定清单的确认流程，并提供中重度入口。
- 原主按钮继承左对齐布局使图标与文字重叠，实机走查发现后改成分开定位。回归检查实际绘制文字留出图标空间，并模拟按下/释放验证禁用与可用状态。
- 确认固定本次清单；取消、切换档位/高级选择及离开页面清除旧确认。进入确认时自动滚到操作区域，避免确认与取消藏在视口下方。
- 自动模式扩大敏感操作过滤范围，未明确允许时不再收缩应用工作集或刷新文件/卷/注册表缓存。显示实际自动项目，空选择不启动自动任务。用假后端验证明确允许前没有请求，允许后才生成请求。
- 统一石墨灰、青绿强调、中文图标导航和精简分组，设置 UI 拆出工作台外壳模块。清理状态使用与监测项相同的可配置绿黄红阈值，关闭状态分色时遵循开关。
- 当前源码通过格式检查、40 项单元测试及 1 项架构测试、严格 clippy 与单任务 release 构建。没有新增运行时依赖。
- 实机走查新版监测项、外观和清理页；实际切换轻度/重度、打开确认并取消，中文及主按钮可见且不重叠。清理记录未产生新的操作。走查后恢复原来的自定义操作列表，其他个性化设置保留。
- `evidence/redesign-running.json` 确认实际发布版运行：监测窗 72×84、topmost=true、toolWindow=true、appWindow=false，设置窗保持普通应用样式。未重做长时间资源压测，不把之前测量数值当作新版本的实测值。
