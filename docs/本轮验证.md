在本机运行的程序上实际打开并检查监测、外观、清理页面与原生右键菜单；图标导航、中文、AI 标识、滑块、分组与空态均可见。用户原有监测项与 47% 背景透明度保留，没有为截图覆盖其设置。

实际连续向右拖动窗口，抵达工作区最右侧后继续向外拖。窗口保持 `[2320, 0, 2560, 142]`，工作区 `[0, 0, 2560, 1392]`，置顶有效，整窗未越界。证据：`evidence/final-right-edge.json`。负坐标显示器、缩放和其他边缘已做规则测试；没有在多显示器现场重复实操全部组合。

资源采样见 `evidence/modern-resources.json` 和 `evidence/final-resources.json`。采样场景为用户当前四个内存指标、2 秒刷新、未展开进程排行、自动清理关闭；首轮 180 秒整机 CPU 平均 0.17%，工作集约 111–112 MiB。此结果不能代表开启全部 GPU、趋势图或进程详情时的开销，也不能据此称为长期稳定性验收。

## 旧验证为何没有拦住问题

1. **还原按钮失效**：此前静态检查仅确认切换分支存在，未跑真实 egui 鼠标交互。小窗口内的 egui 提示层覆盖按钮，下一帧点击被截走。改成窗口外原生提示，并保留工具栏稳定命中区；补按下/释放回归及实机点击。
2. **精简没有数值**：此前测试只覆盖类别分组，允许只画字母。现在测试名称、数值、两块 GPU 和缺失标记，精简模式采用两列名称与数值。
3. **右侧越界**：之前只测释放后的吸附，没有覆盖拖动中的整窗范围和不吸附场景。现在对移动中、释放后和尺寸变化约束整窗；补四边、负坐标、过大窗口测试并实机向右越界拖动。
4. **拖动与悬停切换**：GUI 刷新时机和滚动区域会影响快速拖动；改为 Windows 原生拖动面，并明确保留图标与详情操作区域。跨内容区域和工具栏的鼠标移动不应作为离开整个窗口处理。
5. **操作后测量失败丢记录**：原先后读数错误直接返回总错误，可能丢失已执行项目。现在保留逐项结果，测量失败时不显示内存变化；对应回归覆盖部分成功和读数失败。
6. **自动规则使用旧状态**：刷新失败后仍可能依据旧高负载状态执行。现在读取失败立即停止本轮自动判断；服务回归覆盖该分支和单任务执行约束。
