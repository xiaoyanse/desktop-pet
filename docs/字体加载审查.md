# 字体加载阶段审查

基线 `2391920`，目标为保留中文和既有界面、降低自身常驻私有内存。代码、测试、开发证据工具及文档按三组审查；不调用第三方 AI、CodeGraph 或 AI Mailbox。

## 分组审查

1. Windows 映射及生命周期：检查普通文件、非空和 64 MiB 上限，CreateFileMappingW/MapViewOfFile 失败返回及句柄 RAII。保留禁止写共享的只读 File；Mapping 的借用与自身绑定，缓存由 OnceLock 保存至进程结束。视图释放先于 File 字段释放，不提前释放在用字体地址。没有手写 Send/Sync、裸指针跨层或局部缓冲伪造 static。
2. 接口、装配及 UI：FontSource 只携带标准库 Cow，不把 Win32 或 egui 类型放入接口。系统缓存借用经 from_static 保持到框架；比例/等宽回退顺序与原实现一致，缺字体提示保留。跨层测试集中在仅测试构建的 integration_tests，生产架构限制未放宽。
3. 回归、开发工具及文档：临时映射测试只写入/移除自建夹具，实际查询 MEM_MAPPED/PAGE_READONLY；跨层回归检查 Cow 与指针、四种字体缩放、中文字形和布局。开发工具核实可执行路径后查询目标地址元数据，64 位 FFI 结构与平台定义核对，句柄自动释放、地址/次数受限。工具输出仅含候选字体，不进入产品或后台启动。

## 发现及处理

- 警告，字体复制：原 from_owned 引发 epaint 对整份字体 clone；改为稳定只读映射与 from_static。回归同时检查 UI 生成的 FontDefinitions，不能只凭平台返回 Borrowed 就认定中间没有再次复制。
- 警告，测试误判：视图释放后立即断言该地址 MEM_FREE 会被并行分配复用影响；删除此脆弱断言，检查文件锁实际释放，映射类型在持有期间核实。释放仍由 RAII 源码和真实进程映射检查分别取证。
- 警告，层级：UI 测试直接引用平台实现会违反现有层级守卫；跨层检查移到独立测试目录，UI 只提供 cfg(test) 导出，不扩大生产 API。
- 建议，开发工具可维护性：单次地址空间扫描函数超过 50 行，包含受限顺序 Win32 查询及错误处理。保留为独立开发工具，不引入产品抽象；范围与 ABI 约束在此记录，后续增加其他扫描类型时应拆分。

## 结论与范围

未发现阻断本次本地保存的致命问题。91 项回归、严格 clippy、发布构建、实际 GUI 映射及中文走查的结果见《本轮验证》。映射失败回退和缺少中文字体沿用明确分支，本机没有人为制造系统字体不可读或映射失败；不将这些分支称为实机故障验收。

两版各三分钟冷启动实测支持本机场景下私有占用下降，不能证明长期无泄漏或 CPU 改善。工作集末尾下降不代表应用总内存只有几兆；打开设置/生成报告后的绝对占用另列，不能拿热态和旧冷态比较。原用户对视觉品质的打回仍按真实界面持续纠偏，字体回归不代表设计图复刻已经完成。
