# 内存预算与验收

来源：用户于2026-10-12明确要求“无论在什么状态下，内存占用不超过100兆”，并要求开发和测试持续关注。适用于整个产品，不只宠物空闲状态。当前门禁未通过；本文件是执行约束，不是达标证明。

## 硬性上限与口径

- 按100,000,000字节执行，约95.37 MiB。进程工作集、私有内存、系统记录的生命周期工作集/提交峰值都不得超限；不能用低工作集掩盖高私有提交。
- 监测、设置、螺旋、清理确认、计时提醒、诊断采集与导出，以及未来截图/录音/待办，都适用。并发功能须合并计入，不能给每个窗口或辅助进程各分100 MB。
- 不主动压缩工作集、不重置峰值、不在测量前清缓存制造低值，也不把内存清理功能作用于自身来掩盖超限。
- GPU显存另列诊断；已计入应用工作集/提交的图形驱动和映射内存不扣除。系统外部因素不作为放宽本机实测的理由。

## 开发约束

1. 图片原图与图集留在源码素材目录；运行仅使用构建后的必要切片，按需加载并共享，关闭不用的页面时回收专属资源。现有运行RGBA约2.56 MiB不等于运行总内存。
2. 字体继续保持中文完整显示和只读共享；检查字形/图集缓存、缩放缓存及上传临时副本，不能靠丢失中文或降低可读性达标。
3. 窗口和渲染缓冲按实际需要建立、关闭后释放；实测默认/最小/最大化与缩放，检查多窗口同时存在的峰值。当前渲染开销尚未完成分配归因。
4. 采样与报告维持有界列表、单飞任务及取消，限制冻结文档和中间格式副本；后台不能持续预热未使用功能。
5. 后续截图先计算尺寸和字节预算，再分配；超预算时采用分块或下采样方案，不能先创建超大原始缓冲再丢弃。未实现，不宣称现阶段已支持。
6. 后续录音循环缓冲固定容量，保存采用流式写盘，不将全部音频重复复制到内存；同样需验证与监测/设置并发。录音默认关闭，开发测试使用合成数据。
7. 所有新增功能提交前都有容量估算、实测场景和释放证据。门禁失败时先修复或调整架构，不增加更多常驻功能。

## 当前执行方法与限制

`scripts/measure-resources.ps1 -Seconds 180 -Output evidence/scene.json -EnforceBudget`：每秒记录本项目唯一release进程，附精确字节和系统生命周期峰值。预算默认100,000,000字节，失败先保存完整JSON，再返回非零。旧字段workingSetMB/privateMB实际以MiB表示，以字节字段作验收。

当前脚本要求唯一进程；存在辅助进程时会拒绝开始，不会将其忽略后报达标。下一步需补应用进程组并发测量和短任务峰值取证。三分钟绿色也不证明所有状态永久保证；必须列明已覆盖状态及输入边界。当前已测场景已经明确失败，因此产品内存验收不能通过。
