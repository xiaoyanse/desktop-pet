## 原生复现与修正

旧实现发送根视口 Visible(false)，然后等待200ms，由后续 update 开始选区。固定依赖 eframe0.31.1/winit0.30.13 的本机 Windows 根窗口隐藏后停止 WM_PAINT，RedrawRequested 没有继续抵达 update。只有业务单测无法观察这一原生调度差异。

独立探针初次对照各一次，随后两轮增加透明度、原生穿透样式与恢复帧检查。旧策略三轮均触发3秒保护线程，任务到达时间分别3291/3251/3257ms；透明策略三轮分别450/449/449ms，从程序起点计时，包含最初显示帧等待，均未触发保护线程。后两轮暂停帧72×84所有alpha为0，GL错误为0；恢复帧非零alpha像素3228，GL错误为0。暂停原生鼠标穿透为true，结束为false。日志在 `evidence/screenshot-stage18/`，该目录按既有规则不提交。

最终release构建后运行复验脚本，三轮隐藏策略3036/3036/3032ms，保护线程均触发；透明策略230/248/223ms，均未触发，暂停透明/原生穿透和恢复绘制/交互断言全部通过。最终产物执行结果见 `evidence/screenshot-lifecycle-27952617518f4e8aa272c49c976adbd8/summary.json`。debug与release时间差保留为原始证据，不据此估算真实桌面捕获速度。

修正：根窗口保持可见，截图期间 update 提前返回空画面；clear_color为全透明，并临时穿透鼠标。设置与贴图辅助窗口隐藏。完成/取消/失败后恢复实际记录的鼠标模式，而不是从locked推断。托盘恢复/设置/模式/宠物/退出动作取消未开始的准备或正在捕获的任务。

开发探针使用产品同一暂停/恢复命令，读取的只是自己的合成窗口 framebuffer。保护线程只在显式探针启动时创建；主产品不新增该线程。探针不构造采样、托盘、清理、截图捕获后端、配置持久化或录音；无法借该证据认定桌面截图内容正确。

## 批注输入修正

旧画布先在 drag_stopped 提交，再处理 Esc；取消并清空后，后续 dragged 仍会重新追加点。因此 Esc 与释放同帧可能误提交，异帧取消也可能让笔迹复活。

现在先处理取消，再处理拖动；只有仍存在有效起点的手势才继续追加，释放后取走并清空点集。回归不是只调用 Document.add：使用真实 egui PointerMoved/PointerButton/Key事件，覆盖四种工具绘制、撤销后原图恢复、Esc与释放同帧/异帧、取消后下一笔正常工作。未调用桌面捕获后端。

## 可复验命令

`cargo test --offline --quiet`；`cargo clippy --offline --all-targets -- -D warnings`；`cargo build --offline --release -j 1`；构建后运行 `powershell -NoProfile -File scripts/verify-screenshot-lifecycle.ps1`。

脚本启动自己的小型原生窗口，逐轮检查旧策略卡住与新策略继续、暂停透明/穿透及恢复绘制/交互，不截图桌面、不改剪贴板、不替换运行中的普通实例。每次日志放项目E盘 evidence 独立目录；已存在日志不覆盖。若后续框架升级令旧行为不再复现，脚本报错要求重新评估，不静默沿用旧结论。
