# 视觉纠偏与螺旋：分组审查

基线：943fe53。当前阶段按视觉与素材、领域/应用接线、Windows 区域与诊断三组审查，不调用第三方编码或审查服务。

## 本轮发现与处理

1. 用户截图与设计差距：旧测试只验证点击和布局列宽，没有对真实页面比例及材质作验收。重新检查发布程序的同一页面，保存修改前/后的真实截图；生成玻璃星球和三张材质图，完整提示词与原图落盘。最终风格接受仍由真实效果决定。
2. 材质缩略图被压扁：图集输出为方形，内容为横图；直接把全纹理绘到横向矩形会重复压缩留白。缓存 alpha 主体 UV，再按内容比例绘制；回归检查比例、绘制边界和高度。缓存小尺寸边界，逐帧不重复扫描像素。
3. 预览底部说明裁切、小窗口宠物退化成小点：完整页面回归最初失败并暴露实际剩余空间错误。预览在容器内按剩余高度计算，小窗口降低卡片和分隔间距。回归检查默认/最小窗口说明可见、模式名称可见及宠物最小尺寸；只看说明文字可见不足以阻止宠物退化。
4. 侧栏顶部硬切线：材质从整窗背景层连续绘制，导航不重复铺一块从标题栏下方开始的矩形。
5. 螺旋窗口区域比实际组件大：静态目标矩形包含实际框架没有绘制的底部留白，原生截图出现黑色边缘。区域改为实际 Frame 响应边界，圆角直径与绘制一致，一级图像区域排除透明外圈。动作回归同时检查文字位于实际原生区域。
6. 清理反馈保留：快捷组件显示忙碌/结果消息，长信息截断并提供完整悬浮提示；执行仍需清单确认。检查/取消输入不会调用真实清理后端。

## 代码与边界

原生视觉子代理对默认/小窗外观页和监测页复核：无明确 P1、无中文重叠或明显压扁；两项 P2 为小窗缩略数字偏小和下方选项滚动提示不足。第二次复核确认单个更大数值改善，仍发现滚动提示不明显：AlwaysVisible 只控制出现条件，框架的默认浮动样式还会在静止时淡出。改为占 6 像素的 solid 滚动条并使用前景色，避免把配置常显误报为实机可见。第三次最终截图复核确认默认/最小窗口的亮滑块及轨道可见，解除该 P2；未见变形、中文重叠或预览裁切。默认窗口下方标题部分显示属于明确滚动区域。参考图的反光和内侧高光仍更丰富，不将当前效果描述为像素级复刻或全项目美化验收。

UI 不直接调用 Win32；领域维护布局、顺序动画和输入意图，Windows 适配器检查 PID、实际 DPI 并管理 GDI 句柄。成功设置窗口区域后系统持有该区域，临时区域 RAII 释放；相同边界不重复设置。错误收起入口并给出信息。

没有修改个人监测/清理/计时设置，无新采样线程。透明区域诊断探针采用逻辑坐标 (260,430)，按实际 DPI 换算；该探针只说明一个已知空隙，不替代整个区域或桌面实操。功能组件仍按真实已有能力展示，不加入假报告、截图、录音入口。

验证命令：cargo fmt --all、cargo test -j 1（77 单元 + 2 切图 + 1 架构）、cargo clippy --all-targets -j 1 -- -D warnings、cargo build --release -j 1。结果与实机限制见《本轮验证》；最终视觉复核单列，不把测试绿称为全项目美化完成。
