# 手动资源诊断报告

首版接入设置工作台与螺旋“工具”分支。只在用户点击生成时采集，约两秒差分后保留一份快照；打开页面不采集，关闭设置不会结束正在生成的任务。生成时可取消，取消/失败保留上一份预览。复制和保存使用同一份已冻结 Markdown，而非重新采集。

## 内容与路径策略

- CPU、频率、物理/提交内存、分页与非分页池、当前选择的 GPU/显存、磁盘与网络读数，临时启用全部指标，不更改个人配置。
- CPU 与物理工作集前五名：名称、PID、CPU 全机占比、工作集、私有提交、可核实父进程和可执行路径。
- Node/nodejs、python/pythonw/带版本号的 Python 进程单列，最多 512 项；页面每批 20 项，完整报告包含本次列出的全部项目，超额明确注明。不是后台持续统计或 MCP 会话识别。
- 路径类型在领域层封装，只允许保存脱敏值：Users 下用户名隐藏，Documents/自定义盘目录隐藏，UNC 主机和共享隐藏；保留 Windows、Program Files 及用户 AppData/常见运行时安装目录结构。可执行文件名保留，便于辨认来源。
- 不读取命令行、环境变量、文件内容、窗口内容或剪贴板历史。不根据同一个 node.exe 推断具体 MCP/对话来源；脚本参数没有进入报告。

父进程使用快照内的创建时间比对，时间晚于子进程或查询受限时显示未核实。CPU 差分检查 PID 的创建时间；路径查询再次检查创建时间，避免把重用 PID 的文件路径附在旧进程上。权限不足或已退出保留未知，不自动提权。

工作集包含共享页，不能相加当作整机占用；私有提交不是驻留物理内存，也不能与内核池直接相加。单次内核池快照不能定位驱动泄漏，仍需池标签增长证据。报告不结束进程、不执行真实内存清理。

## 保存与运行开销

“保存到本地”输出 UTF-8 Markdown 至 `%LOCALAPPDATA%\DesktopMeter\reports`，成功后显示实际位置。文件使用时间戳与序号、create_new 创建，不覆盖旧报告；保存失败明确提示，磁盘写入失败时目标文件可能不完整，未宣称保存成功。

生成/保存各使用一个短命工作线程，限制同一时间一项任务；完成后 join 释放，不增加空闲扫描或轮询。采样器、PDH/进程句柄只在采集线程创建/使用/释放。只保留一份预览，原始路径不存入预览对象；界面每次最多铺 20 个运行时进程。没有新依赖，复用已保存且切图合格的报告/剪贴板图片。

职责：`domain/report` 管数据、脱敏和 Markdown；`interfaces/report` 定采集/保存契约；`application/report` 管单任务、取消、异常及冻结文档；Windows `report` 只读采样与 PID 校验；storage `reports` 写文件；UI `work_tools/diagnostic_report` 分入口、固定操作与预览。设置集成测试放在 `settings/tests`，不为测试开放生产私有模块。

开发入口 `--report-probe <文件>` 使用同一采集与渲染链路，写指定验证文件；与日常保存的不覆盖规则分开。现场操作、截图、资源测量及尚未覆盖的平台范围见《本轮验证》。
