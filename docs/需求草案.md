# 桌面资源监视器需求草案

更新时间：2026-10-12。采访已完成，首版已实现；在其他团队修改的基础上继续修订悬停、紧凑模式、颜色分级与贴边功能。

## 已确认的需求

- 项目目录：`E:\projects\043-jianshiqi`。
- 面向 Windows 桌面，应用界面、资源采集和设置逻辑全部使用 Rust 编写。
- 悬浮窗置顶，采用可折叠的小型卡片，支持自由拖动。
- 支持半透明效果，以及颜色和透明度设置。
- 每个指标以数字和细进度条显示；趋势图可按指标单独开启，显示最近一分钟的变化。
- 颜色设置采用简化方案：整体主题色与背景透明度可调整，文字保持清晰，不提供独立文字透明度或逐项配色设置。
- 刷新频率默认 2 秒，设置中可切换为 1、2、5 秒。
- 提供可操作、锁定穿透两种模式；锁定后鼠标操作落到下方应用，通过托盘菜单恢复操作。
- 监测指标可分别开关和调整顺序；同一资源类别中的细项也可以分别开关。
- 支持 CPU、内存、GPU、磁盘、网络资源；支持选择具体设备。
- 不干预其他工作进程，不提供未经授权的结束进程、清理内存或驱动修改行为。
- 需求采访只通过可点选的卡片进行，并明确推荐选项及取舍，不要求用户决定实现技术细节。

## 建议提供的指标

| 类别 | 可选细项 |
|---|---|
| CPU | 占用率、频率 |
| 内存 | 占用率、已用容量、可用容量、提交量、分页池、非分页池 |
| GPU | 利用率、专用显存、共享显存 |
| 磁盘 | 空间使用率、剩余容量、活动率、读取速度、写入速度 |
| 网络 | 上传速度、下载速度 |

指标的可采集性和统计口径需在目标电脑验证。设备不支持或数据暂不可用时，应明确显示状态，不能显示伪造的零值。

默认展示 CPU、内存、逐块 GPU、磁盘读写和网络速度；内存池等细项可按需开启。

## 后续采访项

开机启动首次关闭；设置、位置、指标顺序和开关自动保存。详情显示 CPU / 物理工作集前五名（包含 PID，不提供结束进程）。手动清理仅处理低优先级待机缓存，需要时由辅助进程请求提升权限，不自动清理。

## 本轮修订

- 删除隐藏操作栏的固定布局占位：正常卡片的首行直接显示指标，悬停按钮覆盖在内容上方，显示 / 隐藏不改变窗口尺寸。
- 正常卡片保持 240 逻辑像素宽；精简状态只显示资源指示标志，默认约 168 × 32 逻辑像素（随已开启的类别 / 显卡数变化）。精简状态不展开详情，不持续扫描进程。
- 精简状态的 Windows 原生悬停提示位于应用窗口之外，不扩展指示条；双击恢复正常，右键菜单 / 托盘 / 设置也能切换。
- 默认百分比 70% 为黄色、90% 为红色，其余为绿色；黄色 / 红色阈值可调整。可用内存和剩余磁盘反向判断；提交 / 专用显存以容量比例判断。未知数据为灰色，无固定容量的速度 / 频率 / 内核池保持主题色。
- GPU 和磁盘活动颜色表示负载，不将繁忙本身定义为泄漏；其他团队的连续超限 10 秒判断保留为压力标记。
- 背景、边框独立开关；同时关闭时保留文字和指示标志。设置持久化，兼容版本 2 配置并保留原有红色阈值、设备、顺序和开关。
- 自动贴边默认开启，可关闭；释放拖动后在 16 逻辑像素范围内吸附当前显示器四边工作区域，支持缩放和负坐标显示器；贴到右 / 底部后切换大小保持贴边。
- 外观 / 阈值 / 顺序修改仅重绘和保存，不触发额外系统采样；采集类别、设备和刷新间隔变化才更新采样器。

## 实现原则与验收方向

- 使用 Rust 原生桌面界面，不使用网页界面或 JavaScript/TypeScript 应用层。
- 避免用反复启动外部程序的方式采集数据；采集和绘制解耦，避免界面等待采样。
- 只对开启的采集类别维持必要的采样，合并同类指标的查询，并合理控制历史数据长度。
- 普通常驻运行优先使用无管理员权限可用的接口；必要权限和指标支持范围以实测为准。
- 在目标电脑验证置顶、透明度、拖动、穿透与解锁、多设备选择、排序和开关。
- 实测应用自身的内存和 CPU 占用，再给出性能结论，不提前承诺未经测量的数值。
- 采访结束后整理最终需求与首版范围，再开始实现。
